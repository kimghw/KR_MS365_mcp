# 멀티유저 구현 2차 검토 (astra)

## 요약 판정

**현재 상태로는 출시 불가다. 확인된 High 차단 이슈 1건이 남아 있다.** lease 이후 재검사와 현재 요청 identity 검사는 구현됐지만, 토큰을 이미 받은 다단계 작업이 후속 외부 변경 전에 권한을 재검사하지 않는다. 공개 Outlook 첨부 저장 경로의 실제 구현에 인증·HTTP 대체물을 연결한 메모리 재현에서, 키 폐기를 반영한 뒤에도 **새 OneDrive 폴더 POST 2건**이 호출됐다. OAuth 연결 해제 경합, 변환 worker 수명, drain 완료 판정, URL 정책, 마이그레이션 동결·검증에도 미해결 사항이 있어 “전부 반영 완료” 판정은 수용할 수 없다.

1차 대비 **lease 대기 직후의 폐기 검사, Outlook의 무제한 페이지 작업 선생성, OAuth 콜백끼리의 경합, 부분 성공 오류 원문 노출, 첨부 저장 경로 인코딩, 검증 handle 사용, pending 상한 경합**은 수정됐다.

검토 기준은 현재 작업 트리다. 파일은 수정하지 않았다. 아래 재현은 실제 구현 함수와 메모리 대체물을 사용했으며, 실 Entra·Graph 호출은 하지 않았다. **1,368 passed, 4 skipped는 구현팀 보고값**으로, 전체 pytest와 최종 수치는 이번 검토에서 재확인하지 않았다.

**R04·R09 — ④ 잔여 설명의 정확성**

교차 프로세스 drain이 없고 이미 시작된 로컬 저장이 계속될 수 있다는 설명은 맞다. 그러나 관리 CLI는 별도 프로세스의 로컬 풀만 drain하며, 다른 도메인 프로세스의 작업 종료를 확인하지 않는다. “토큰 획득·응답 전 검사로 차단”도 **그 검사 시점의 차단**으로 한정해야 한다. 이미 받은 토큰을 재사용하는 후속 Graph 변경은 N01처럼 계속될 수 있다.

변환 thread를 강제 종료하지 못한다는 설명도 맞지만, 현재는 실제 thread보다 temp·lease가 먼저 정리되고, 슬롯도 `FileManager` 인스턴스별이다. 서비스 교체 후에도 살아 있는 이전 worker를 포함한 사용자별 상한을 보장하지 않는다.

## 테스트 공백

1. **폐기 이후 후속 HTTP 호출 차단**  
   lease 대기 시험 외에 첫 Graph 응답·배치·폴더 확인·upload chunk·재시도 사이에서 revoke·만료·disable·disconnect를 발생시켜야 한다. 이후 **새 외부 변경 호출 0건**을 검증해야 한다.

2. **OAuth 연결 생애 전체의 동시성**  
   콜백끼리의 동시 완료뿐 아니라 disconnect의 epoch 변경과 토큰 삭제 사이에 새 연결을 완료시키는 시험이 필요하다. 성공한 연결의 registry 상태와 토큰 존재를 함께 확인해야 한다.

3. **실제 다중 프로세스 삭제·drain**  
   관리 CLI와 도메인 서버를 별도 프로세스로 실행하여 삭제 중 로컬 저장·변환·서비스 초기화가 끝났는지 검증해야 한다. 로컬 pool에서도 invalid 재lease와 지연된 `close()`를 포함해야 한다.

4. **반복 취소·timeout·퇴거의 결합**  
   기존 반복 취소 시험과 timeout 시험은 각각의 경우만 다룬다. timeout 후 실제 converter가 남은 상태에서 temp·lease·drain·서비스 재생성·총 worker 수를 함께 검증해야 한다.

5. **자원 상한의 전체 적용**  
   14개 인자의 경계값, 로컬 directory 201개 이상, Outlook 대형 첨부 decode·변환, 제한 전 전체 파일 읽기, 반복 저장 누적량을 검증해야 한다. 반환 문자열 절단과 처리 중 메모리 제한도 별도로 측정해야 한다.

6. **URL 정책의 공통 회귀 시험**  
   모든 구현에 동일한 trailing-dot·사설 DNS·DNS 실패·userinfo·비표준 포트·인코딩 slash/dot 시험을 적용해야 한다. Outlook upload-session의 301/302/307/308에서 청크 본문이 재전송되지 않는지도 확인해야 한다.

7. **마이그레이션 writer와 내용 무결성**  
   포트를 열지 않는 mode 0 FileHandler·stdio writer 및 이미 생성된 저장소를 대상으로, 마지막 fingerprint 검사 직후 쓰기를 교차 실행해야 한다. 동일 행 수·owner를 유지한 DB payload·ID 변경도 staging/live 검증이 거부해야 한다.

8. **실환경 및 호환성**  
   실제 Entra 왕복·실 Graph 호출, percent-encoded Teams chat ID와 OneDrive 파일·폴더명, Windows handle·reparse/hardlink 교체 경합은 미검증이다. mode 0의 명시적 import뿐 아니라 기존 세 wildcard import 계약도 회귀 대상에 포함해야 한다.
